## Scope
Root/service agent guidance, feature/bug/design/docs issue templates, PR template, branch/rules/review instructions.

Excluded/deferred: Merging, rewriting history or changing production settings without authorization.

## Acceptance criteria
- [ ] EP01-05-AC1: Root/nested guidance describes trust boundaries, ownership, testing, evidence and approval requirements without contradictions.
- [ ] EP01-05-AC2: Issue templates require goal, assumptions, AC, requirement/test IDs, dependencies, ownership, rollout and evidence; PR template links issue and checks.
- [ ] EP01-05-AC3: Document/configure agreed branch and review rules using authorized repository capabilities; blocked settings remain explicitly blocked.
- [ ] EP01-05-AC4: Exercise a sample issue/review and verify templates and instructions; attach evidence and avoid treating status as proof.

## Technical ownership
AGENTS.md, apps/**/AGENTS.md, services/**/AGENTS.md, .github/ISSUE_TEMPLATE/**, .github/pull_request_template.md, CONTRIBUTING.md

## Security and edge cases
No committed secrets or maintainer account dependency; preserve tenant/fork boundaries. Fail closed on invalid enabled configuration. Never mark runtime or provider integration ready from scaffold checks alone.

## Verification and evidence
Run issue-specific positive, negative and boundary checks. Record commands, actual results, date, revision and limits under docs/test-evidence/. Unexecuted acceptance stays unchecked.

## Definition of done and rollout
All applicable AC verified, implementation reviewed, documentation/tests updated and evidence linked to a commit. No unresolved blocker. Deliver reviewable changes; commit/push/merge and production changes require authorization. Bootstrap or adopt incrementally; no production data migration in this issue.
