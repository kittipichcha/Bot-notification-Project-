## Scope
GitHub Actions formatting, types/build, unit/integration/contract checks, dependency/secret scans, server-side PR branch/issue governance checks, and the declarative `main` ruleset specification.

Revised specification reconciliation: EP01-03 owns server-side CI checks (`.github/workflows/**`, `.github/rulesets/main-protection.json`, `.editorconfig`, `.gitleaks.toml`, `scripts/check-*.js`, and root `package.json` check scripts). Local developer worktree scripts (`scripts/create-worktree.sh`, `scripts/cleanup-worktree.sh`), `AGENTS.md`, `CONTRIBUTING.md`, and issue/PR templates remain owned by EP01-05.

Excluded/deferred: Production release and deployment automation; repository/local contributor workflow docs and templates owned by EP01-05.

## Acceptance criteria
- [x] EP01-03-AC1: Clean installs use committed lockfiles; workflows run on PRs with minimal permissions.
- [x] EP01-03-AC2: Formatting/type/build and meaningful unit/integration/contract failures produce failing required checks.
- [x] EP01-03-AC3: Secret scan rejects a synthetic test-token fixture and dependency scan reports actionable failures without exposing real credentials.
- [x] EP01-03-AC4: Verify a deliberately failing sample PR is blocked by configured checks; attach actual run/commit evidence and note rules dependency.

## Technical ownership
.github/workflows/**, .github/rulesets/main-protection.json, .editorconfig, .gitleaks.toml, scripts/check-*.js, root/service check scripts

## Security and edge cases
No committed secrets or maintainer account dependency; preserve tenant/fork boundaries. Fail closed on invalid enabled configuration. Never mark runtime or provider integration ready from scaffold checks alone.

## Verification and evidence
Run issue-specific positive, negative and boundary checks. Record commands, actual results, date, revision and limits under docs/test-evidence/. Unexecuted acceptance stays unchecked. See [EP01-03 evidence](../test-evidence/EP01-03.md).

## Definition of done and rollout
All applicable AC verified, implementation reviewed, documentation/tests updated and evidence linked to a commit. No unresolved blocker. Deliver reviewable changes; commit/push/merge and production changes require authorization. Bootstrap or adopt incrementally; no production data migration in this issue.
