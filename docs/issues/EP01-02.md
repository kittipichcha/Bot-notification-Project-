## Scope
- OpenAPI, JSON Schemas, shared DTOs/enums, schema versions and canonical first-party route registration rules.
- Developer-owned platform, tool, trigger, model, agent, request/approval, bot-connection, response and budget configuration contracts.
- Reproducible generated TS/Python types, runtime validation, reviewed extensible catalogues and negative fixtures.
- Explicit P0/P1/P2 gates, clause/test ownership and dated evidence.

Deployment maintainers own supported file-based schemas/defaults/limits. PostgreSQL stores authorized user choices and runtime grants, requests and approval records; configuration listings do not grant permission. Secrets remain in the environment or a secret provider.

## Acceptance criteria
Existing AC1–AC4 identifiers are retained and clarified; AC5–AC8 close the revised-document coverage gaps. All remain unchecked until their full revised scope is verified.

- [ ] **EP01-02-AC1 — Canonical API contracts.** Cover the approved enabled P0 API inventory with strict path/query/body, success and error schemas, stable operation IDs and shared DTOs. Use the approved common error shape `{code,message,field_errors:[{field,message}],trace_id,retryable}`, rather than treating the old provisional nested envelope or unrestricted `data` as an endpoint contract. Define canonical `/api/v1` registration and rejection of legacy application routes; retain the separate health, provider-webhook and transaction-landing namespaces. Do not fabricate handlers or register unimplemented/disabled routes. Runtime owners supply handlers. API-029–031 must remain unregistered in P0/P1.
- [ ] **EP01-02-AC2 — Generated types and validation.** Generate usable TS/Python types from the canonical schemas with documented, pinned commands; no manual edits to generated types. Validate representative valid/invalid cases, required versus omitted/null fields, enums, limits and references in both runtimes. Resolve schemas only through the trusted local catalogue. Repeated generation is deterministic; non-mutating drift checks reject changed, missing and extra artifacts.
- [ ] **EP01-02-AC3 — Extensible, fail-closed registry.** Preserve developer-controlled adapter registration, immutable validated declarations and readiness/feature/grant checks. Unknown or wrong-role adapters and malformed configuration fail before dispatch. Configuration alone cannot install or activate code. Extend TC-PLATFORM-005 beyond empty tool lists: add a trusted mock adapter with all six role callbacks and a distinct reviewed tool/argument/result schema through catalogue/configuration changes, without orchestration switch changes. Reject duplicates, unknown references, invalid arguments/results and missing implementations. Replace literal `safe_tool`/`tool_input` restrictions with trusted catalogue lookup. Default lifecycle event policy stays restricted to approved system handlers; this does not enable personal watches.
- [ ] **EP01-02-AC4 — Revised-source traceability.** Map each applicable source clause through AC, schema/config/generated artifact, test, evidence and runtime owner. Include TC-CONTRACT-002/NFR-INT-01 and the shared API contract responsibilities. Preserve prior evidence under its original source revision; it is not proof of revised acceptance. Keep release/dependency mappings consistent and require dated commit-linked evidence for completion.
- [ ] **EP01-02-AC5 — Canonical FinalResponse and trust boundary.** Define and generate the trusted `FinalResponse` with `text,status,extra_response,source_refs,stale,error_code?` and supported canonical P0 component contracts. Represent backend-created opaque `action_ref`/trusted transaction references where required. Keep a separate strict model-proposal type: models cannot mint action references, handler IDs, tickets, tokens or arbitrary executable URLs. Test accepted canonical responses and rejected forged proposal fields. Rendering, signed-reference issuance, approval execution and delivery remain downstream.
- [ ] **EP01-02-AC6 — Complete catalogue and policy shapes.** Tool metadata represents unique IDs, provider actions, READ/WRITE class, argument/result schemas, scopes and rate-limit rules. Trigger metadata represents sources, reviewed payload/filter schemas, eligible roles and system handlers. Cover the Configuration Reference's model catalogue/parameter rules, agent modes/roles/four-call cap, request deadlines/retries, exact-action approval policy/expiry, bot-connection policy, response and budget settings. Validate supported entries, types, bounds and cross-field rules at startup; provide reusable validation for authorized-setting services. Record ownership of each policy. Do not invent TBD project defaults: enabled features require explicit valid configuration, with unresolved decisions assigned to the owner.
- [ ] **EP01-02-AC7 — TC-CONTRACT-002 round-trip parity.** Assert both runtimes use the same canonical schema identities/versions and reject unsupported versions. Perform bidirectional TS/Node → Python → TS/Node serialization/validation for representative DTOs, preserving nested fields, enums, null versus omission, Unicode and timestamps. Generated imports, fixture verdict agreement and drift checks alone do not satisfy this test. Record actual results as EV-CONTRACT-002.
- [ ] **EP01-02-AC8 — Release gates and safe defaults.** P0 contracts support the approved managed Discord/SIMPLE scope; disabled P1/P2 declarations may remain without activation. Reject out-of-release selections and invalid configuration without leaking values. Preserve default-deny access, backend-only identity/approval decisions, the shared four-call ceiling and protected budget reserve. Do not promote P1/P2 positive cases into P0 or make later-priority runtime work a prerequisite for P0.
